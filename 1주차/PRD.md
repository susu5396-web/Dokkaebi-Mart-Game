# 도깨비 마트 1주차 PRD

작성일: 2026-11-05  
기준 문서: [PRE_PRD.md](PRE_PRD.md)  
개발 환경: Windows / Python / pico2d  
상태: 구현 기준 초안

## 1. 목표와 범위

**세부 디자인을 먼저 준비하고, 디자인을 적용한 기본 화면에서 닉네임 입력과 1단계 선택까지 실행할 수 있게 만든다.**

이번 주에는 캐릭터 애니메이션 스프라이트, 마트·매대뷰·상품·UI 디자인을 준비한다. 코드에서는 시작·닉네임 입력, 로비·스테이지 선택, 엔딩 미리보기를 구현한다. 실제 장보기 기능과 연결된 화면의 최종 완성은 게임 구현 후 진행한다.

수정된 PRE-PRD의 ‘시작,닉네임 입력 → 로비,스테이지 선택’은 다음 두 화면으로 묶는 구성으로 해석한다.

- **시작 화면:** 게임 제목, 닉네임 입력, 게임 시작, 종료.
- **로비 화면:** 닉네임, 기여도 표시 영역, 1·2단계 선택, 로그아웃.

엔딩은 별도 화면으로 준비하며 개발용으로 확인한다. 실제 플레이 대신 선택 결과를 확인하는 임시 스테이지 화면을 둔다.

### 이번 주 구현 경계

| 이번 주 구현 | 이후 연결 |
| --- | --- |
| 닉네임 입력과 실행 중 상태 보관 | 닉네임별 기여도 파일 저장 |
| 1단계 선택, 2단계 잠금 표시 | 실제 1단계 성공에 따른 2단계 해금 |
| 스테이지 선택 결과와 로비 복귀 | 마트 탐색·상품 수집·계산 |
| 디자인 리소스 표시와 화면 전환 | 캐릭터 이동·도깨비 행동·공격 |
| 엔딩 미리보기 | 공용 자금 목표 달성에 따른 엔딩 진입 |

## 2. 디자인 작업 목록

진행 순서는 **세부 디자인 준비 → 화면 배치 확정 → 코드에 적용**으로 한다. 디자인마다 필요한 파일을 목록으로 관리하고, 완성본과 임시본을 구분한다.

- [ ] 플레이어 캐릭터 기본 외형과 이동·공격 애니메이션 스프라이트 제작.
- [ ] 도깨비 기본 외형과 이동·탈취·도주·피격 애니메이션 스프라이트 제작.
- [ ] 카트와 빗자루 이미지 제작.
- [ ] 마트 탑뷰 지도, 통로·매대·계산대·도깨비 등장 구역 디자인.
- [ ] 매대뷰 배경과 상품 배치 영역 디자인.
- [ ] 유제품·빵·화장품·야채·과일 상품 이미지와 구별 가능한 이름 준비.
- [ ] 시작 화면, 로비·선택 화면, 엔딩 화면 디자인.
- [ ] 버튼, 입력창, 잠금 표시, 장보기 목록, 인벤토리, 시간·자금 표시 UI 디자인.
- [ ] 안내·오류·엔딩 문구 정리.
- [ ] 이미지 파일명, 크기, 스프라이트 프레임 순서와 기준점 기록.
- [ ] 사용할 한글 글꼴과 외부 리소스 출처 정리.

애니메이션의 방향 수와 프레임 수, 상품 이미지 수량은 제작 시작 전에 작업량에 맞게 정한다. 이번 주 코드에 모든 게임용 이미지를 연결할 필요는 없으며, 화면에서 사용하는 리소스부터 적용한다.

## 3. 실행 흐름

```text
실행
  → 시작 화면에서 닉네임 입력
  → 입력 검사 통과 후 로비
  → 1단계 선택
  → 임시 스테이지 화면
  → 로비 복귀

로비에서 로그아웃 → 닉네임·해금 상태 초기화 → 시작 화면
개발 모드의 로비 → 엔딩 미리보기 → 로비 복귀
종료 버튼 / Esc / 창 닫기 → 정상 종료
```

2단계는 이번 주 기본 실행에서 항상 잠겨 있다. 임시 스테이지 진입·복귀와 엔딩 미리보기는 성공 판정이나 보수 지급을 발생시키지 않는다.

## 4. 화면별 구현 요구사항

### 4.1 시작·닉네임 입력 화면

**표시 요소**

- 제목 `도깨비 마트`, 부제 `도깨비의 장보기 소동`.
- 닉네임 입력창, 입력 안내, 게임 시작 버튼, 종료 버튼.
- 입력 오류 문구를 표시하는 영역.

**입력과 처리**

1. 처음 진입하면 닉네임은 빈 값이며 입력창에 포커스를 둔다.
2. 입력창 클릭 시 포커스를 얻고, 입력된 문자를 편집 중 문자열에 추가한다.
3. Backspace는 마지막 문자 하나를 삭제한다. 빈 값에서는 아무 동작도 하지 않는다.
4. Enter 또는 게임 시작 버튼을 누르면 동일한 닉네임 검증 함수를 호출한다.
5. 앞뒤 공백을 제거한 값이 비어 있으면 `닉네임을 입력해 주세요.`를 표시하고 현재 화면을 유지한다.
6. 유효하면 정리된 닉네임을 세션에 저장하고 로비로 전환한다.
7. 오류 이후 값을 수정하면 이전 오류를 지우고 다시 제출할 수 있게 한다.

**초기 입력 규칙 제안**

- 최대 12자. 초과 입력은 반영하지 않고 길이 제한 안내를 표시한다.
- 영문·숫자 입력을 먼저 검증한다. 한글 입력 지원은 사용 중인 pico2d 입력 이벤트에서 조합 입력을 확인한 후 확정한다.
- 한글 글꼴 표시와 한글 입력 지원은 별개로 확인한다. 실제 지원하는 입력 범위는 입력창에 안내한다.
- 같은 닉네임을 금지하거나 계정·비밀번호 검사를 추가하지 않는다. 원기획은 같은 닉네임의 기여액을 합산한다.

12자 제한과 문자 지원 범위는 PRE-PRD에 없는 구현 제안이며, 입력 기능 제작 전에 확정한다.

**완료 기준:** 유효한 닉네임으로 로비에 진입하고, 빈 값·공백만 있는 값으로는 진입할 수 없다.

### 4.2 로비·스테이지 선택 화면

**표시 요소**

- `{닉네임}님, 도깨비 마트에 오신 것을 환영합니다.`
- 1단계 버튼: `도깨비 1마리` 안내.
- 2단계 버튼: `도깨비 2마리` 안내와 잠금 표시.
- 개인 기여액·공용 자금·목표액을 표시할 영역.
- 로그아웃 버튼과 종료 버튼.

**입력과 처리**

1. 로비 진입 시 세션의 닉네임과 해금 상태를 읽는다.
2. 1단계 클릭 시 `selected_stage = 1`로 기록하고 임시 스테이지로 이동한다.
3. 2단계 클릭 시 잠금 상태를 검사한다. 잠겨 있으면 이동하지 않고 `1단계를 완료하면 선택할 수 있습니다.`를 표시한다.
4. 잠금은 그림으로만 표현하지 않고 클릭 처리에서도 검사한다.
5. 로그아웃 시 닉네임·선택 단계·접속 중 해금 상태를 초기화하고 시작 화면으로 돌아간다.
6. 개발 모드에서만 엔딩 미리보기 버튼을 표시한다.

**표시용 데이터**

- 이번 주 기여액·공용 자금은 `0원 (임시)`로 표시한다.
- 목표액은 `미정`으로 표시한다. 임의의 금액을 확정 규칙으로 넣지 않는다.
- 순위 영역이 디자인에 있으면 빈 상태를 표시한다. 가상의 사용자 기록을 실제 기록처럼 넣지 않는다.
- 저장·불러오기는 4주차 작업이며 로그아웃 처리와 영구 데이터 삭제를 연결하지 않는다.

**완료 기준:** 닉네임이 유지되고 1단계 선택이 가능하며, 2단계 클릭은 잠금 안내만 발생시킨다.

### 4.3 임시 스테이지 화면

이 화면은 1단계 선택이 코드에서 정상 전달되었는지 확인하기 위한 화면이다.

- 세션의 선택 단계를 읽어 `1단계를 선택했습니다.` 표시.
- `장보기 기능은 개발 중입니다.` 안내와 로비로 버튼 표시.
- 로비 복귀 시 선택 단계만 비우고 닉네임은 유지.
- 성공·보수·해금 처리는 수행하지 않음.
- 이후 실제 게임 화면으로 교체할 수 있도록 별도 화면으로 구성.

**완료 기준:** 선택한 단계가 정확히 표시되고 로비로 복귀해 다시 선택할 수 있다.

### 4.4 엔딩 미리보기 화면

- 제목 `도깨비 마트 인수 완료!`와 결말 문구 표시.
- 준비한 마트·캐릭터 디자인 적용.
- 개발용 진입임을 알리는 `엔딩 미리보기` 문구 표시.
- 로비로 버튼과 종료 버튼 제공.
- 미리보기 전후 닉네임·해금·기여액·공용 자금을 변경하지 않음.

결말 문구 초안: `모두가 모은 장보기 보수로 마트를 인수했습니다. 이제 우리의 마트에서 새로운 이야기가 시작됩니다.`

실제 엔딩 조건은 성공 보수 반영 후 공용 자금이 목표액에 도달했는지 검사하는 것으로, 4주차에 연결한다. 실제 엔딩 이후 진행 방식은 별도로 결정한다.

**완료 기준:** 개발 모드에서 미리보기에 진입하고 상태 손실 없이 로비로 돌아온다. 개발 모드를 끄면 진입 버튼이 보이지 않는다.

## 5. 공통 코드 설계

### 5.1 파일 구성

현재 `1주차/main.py`는 비어 있다. 다음 구조를 기준으로 필요한 파일을 순서대로 만든다.

```text
1주차/
  PRE_PRD.md
  PRD.md
  main.py
  settings.py
  session.py
  scene_manager.py
  ui.py
  scenes/
    __init__.py
    title_scene.py
    lobby_scene.py
    stage_preview_scene.py
    ending_scene.py
  assets/
    images/
    fonts/
```

| 파일 | 책임 |
| --- | --- |
| `main.py` | 창 초기화, 이벤트 수집, 시간 계산, 화면 갱신·출력, 종료 |
| `settings.py` | 창 크기, 제목, 개발 모드, 닉네임 길이 제한, 리소스 경로 |
| `session.py` | 현재 닉네임·선택 단계·접속 중 해금 상태와 초기화 |
| `scene_manager.py` | 현재 화면 보관, 전환 예약과 적용 |
| `ui.py` | 공통 버튼 표시·클릭 판정, 닉네임 입력창 |
| `scenes/` | 각 화면의 입력 처리와 그리기 |

창 크기와 이미지 배치 좌표는 디자인 확정 후 `settings.py`와 화면 구성에 반영한다.

### 5.2 세션 데이터

| 필드 | 초기값 | 변경 시점 |
| --- | --- | --- |
| `nickname` | 빈 문자열 | 유효한 닉네임 제출, 로그아웃 |
| `selected_stage` | `None` | 1단계 선택, 임시 화면에서 복귀, 로그아웃 |
| `stage2_unlocked` | `False` | 이번 주에는 유지, 향후 실제 1단계 성공 시 변경 |

`reset_session()`은 위 세 필드를 초기값으로 되돌린다. 기여액과 공용 자금은 향후 영구 저장 데이터로 분리한다. 이번 주 화면의 임시 표시 값을 실제 보상 데이터로 취급하지 않는다.

### 5.3 화면 인터페이스와 전환

각 화면은 다음 역할을 갖는다. 메서드 이름은 구현 시 동일하게 사용한다.

- `enter()`: 화면 진입 시 안내 문구·입력 포커스 등 임시 상태 초기화.
- `handle_event(event)`: 현재 화면의 키보드·마우스 입력 처리.
- `update(dt)`: 필요한 화면 애니메이션과 시간 기반 상태 갱신.
- `draw()`: 배경, 이미지, 문구, UI 출력.
- `exit()`: 입력 포커스와 화면 전용 상태 정리.

화면 전환 요청은 즉시 중첩 실행하지 않고 관리자에 예약한다. 현재 이벤트 처리가 끝나면 이전 화면의 `exit()`를 호출하고 새 화면의 `enter()`를 호출한다. 전환이 예약되면 해당 프레임의 남은 화면 입력은 소비해 같은 클릭이나 Enter가 새 화면에서 재처리되지 않도록 한다.

### 5.4 게임 루프와 종료

1. 설정을 읽고 pico2d 창과 화면 공용 리소스를 초기화한다.
2. 시작 화면을 활성화한다.
3. 매 프레임 이벤트를 모으고 창 닫기·Esc를 우선 처리한다.
4. 종료 요청이 없으면 현재 화면에 이벤트를 전달한다.
5. 예약된 화면 전환을 적용하고 `update(dt)`를 수행한다.
6. 화면을 지운 뒤 현재 화면을 그려 갱신한다.
7. 종료 요청 시 루프를 빠져나오고 창을 닫는다.

종료 버튼, Esc, 창 닫기는 하나의 종료 요청 경로를 사용한다. 화면마다 독립적인 게임 루프를 만들지 않는다.

### 5.5 공통 버튼과 좌표 처리

- 버튼은 표시 영역과 클릭 영역에 동일한 위치·크기를 사용한다.
- 마우스 올림 상태와 기본 상태를 구분한다.
- 왼쪽 버튼을 누른 이벤트 한 번에 동작 한 번만 수행한다. 누른 채 유지하는 동안 반복 실행하지 않는다.
- 입력 이벤트 좌표와 그리기 좌표의 원점 차이를 확인하고, 필요하면 공통 변환 함수에서 Y좌표를 변환한다.
- 모든 화면이 같은 변환을 사용하며 버튼마다 별도 보정을 넣지 않는다.
- 2단계 잠금 버튼은 선택 대신 잠금 안내를 보여 주는 동작을 갖는다.

### 5.6 리소스 처리

- 소스 파일 위치를 기준으로 `assets` 경로를 계산한다.
- 이미지·글꼴을 매 프레임 다시 읽지 않는다. 초기화 또는 첫 화면 진입 시 로드하고 재사용한다.
- 한글 문구가 표시되는 글꼴인지 확인한다.
- 리소스가 없을 때는 누락된 파일 경로를 확인할 수 있는 오류를 남긴다.
- 스프라이트 프레임 규격을 기록하되, 실제 이동·전투 애니메이션 제어는 이후 주차에서 연결한다.

## 6. 구현 순서와 산출물

| 순서 | 작업 | 완료 결과 |
| --- | --- | --- |
| 1 | 디자인 목록, 화면 배치, 문구와 리소스 규격 정리 | 코드에 적용할 화면 시안과 파일 목록 |
| 2 | 세부 디자인 제작 및 화면용 리소스 준비 | 시작·로비·엔딩에 사용할 이미지와 글꼴 |
| 3 | 실행 환경 확인, 설정과 기본 루프 작성 | 창 실행·정상 종료 |
| 4 | 세션과 화면 관리자 작성 | 화면 전환과 상태 전달 가능 |
| 5 | 공통 버튼·입력창, 시작 화면 구현 | 닉네임 검증 후 로비 진입 |
| 6 | 로비와 임시 스테이지 구현 | 잠금 처리, 1단계 선택, 복귀, 로그아웃 |
| 7 | 엔딩 미리보기 구현 | 개발 모드에서 진입·복귀 |
| 8 | 디자인 적용 상태와 전체 흐름 검증 | 수정 결과와 미완료 작업 기록 |

리소스 제작이 지연되면 미완료 항목을 기록한다. 임시 리소스로 기능을 검증하는 경우에도 디자인 완료와 코드 완료를 따로 관리한다.

## 7. 검증 기준

| ID | 확인할 동작 | 기대 결과 |
| --- | --- | --- |
| T01 | 실행 후 종료 버튼·Esc·창 닫기를 각각 사용 | 오류 없이 종료 |
| T02 | 빈 닉네임과 공백만 있는 닉네임 제출 | 안내 표시, 시작 화면 유지 |
| T03 | 닉네임 입력·Backspace·제출 | 수정한 값이 로비에 표시 |
| T04 | 닉네임 길이 경계와 초과 입력 | 확정한 제한 적용, 입력창 밖으로 넘치지 않음 |
| T05 | 앞뒤 공백을 포함한 닉네임 제출 | 정리된 닉네임 보관 |
| T06 | 잠긴 2단계 클릭 | 안내만 표시, 선택 단계 변경 없음 |
| T07 | 1단계 선택 후 로비 복귀 | 단계 전달 정상, 닉네임 유지, 2단계 잠금 유지 |
| T08 | 로그아웃 후 다시 시작 | 닉네임·선택 단계·해금 상태 초기화 |
| T09 | 엔딩 미리보기 진입 후 복귀 | 세션 상태 유지, 보상·해금 발생 없음 |
| T10 | 개발 모드를 끄고 로비 확인 | 엔딩 미리보기 버튼 숨김 |
| T11 | 화면 전환을 3회 반복하고 버튼을 길게 누름 | 중복 전환·이전 화면 입력 잔류 없음 |
| T12 | 프로젝트 루트와 1주차 폴더에서 각각 실행 | 두 실행 위치에서 리소스 경로 정상 |
| T13 | 화면의 글꼴·이미지·클릭 위치 확인 | 한글 깨짐·잘림·겹침·클릭 영역 어긋남 없음 |

이번 주에는 실제 창에서 위 흐름을 수동 검증한다. 닉네임 검증과 세션 초기화는 UI와 분리해 잘못된 입력이나 상태 문제를 독립적으로 확인할 수 있게 한다.

## 8. 완료 기준과 남은 결정

### 1주차 완료 기준

- [ ] 디자인 작업 목록의 진행 상태와 미완료 리소스가 기록되어 있다.
- [ ] 시작 화면에서 닉네임을 입력하고 로비에 진입한다.
- [ ] 1단계를 선택하고 로비로 돌아오며, 2단계 잠금이 유지된다.
- [ ] 로그아웃 시 접속 상태가 초기화된다.
- [ ] 엔딩 미리보기를 확인하고 복귀한다.
- [ ] 화면에 준비한 디자인이 적용되어 있다.
- [ ] 검증 항목을 확인하고 실행을 막는 오류를 수정했다.
- [ ] 실행 방법, 필요한 라이브러리와 남은 작업을 기록했다.
